# Local model server

Uses the official Jev HTTP API, the installed `laya` Python package, and one OpenRouter model. No simulated fallback exists. A failed or invalid response remains a failed run.

Use an existing Python environment containing `laya==0.3.4`, or create a stable ignored runtime in the demo root:

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r server/requirements.txt
```

Run from the demo root (replace `python` below with `.venv/bin/python` if using that environment):

```bash
python server/prepare_laya.py
# Use process environment, or an explicitly chosen external credential file:
export DEMO_ENV_FILES=/absolute/path/to/your/existing.env
python -m server.app --port 8787
```

`DEMO_ENV_FILES` accepts colon-separated external files and imports only `TYPESAFE_API_KEY`, `OPENROUTER_API_KEY` and `OPEN_ROUTER_API_KEY`. Existing process variables win. Files are parsed as literal values; never sourced as shell code. Both OpenRouter key spellings are accepted. Nothing is copied into this repository. `LAYA_DEVICE=mps`, `cpu` or `cuda` is optional; default is the official runtime's automatic device choice.

The runtime is not reinstalled by the server. For a new environment, install `laya==0.3.4` using your package manager. Tested Python 3.12 / laya 0.3.4 / torch 2.14.0 / transformers 5.17.0. The pinned multilingual checkpoint is `convaiinnovations/laya-multilingual@052592a15d198d9ad47da779604259b10b47b7aa`; `prepare_laya.py` downloads only its weights/config/tokenizer files from the official repository. Loading happens once, outside inference timing. `/api/health` reports actual device, dtype, versions and load time.

The two decision stages share exactly the same question builder across Jev and Laya. Stage 1 chooses theme/layout and independently judges each section; stage 2 chooses density/type/corners/emphasis/hero and the first section. Other chosen sections retain catalogue order. Text in only modes is prepared catalogue copy (or retained previous copy), not language generated by the decision model. Section inclusion threshold is 0.5. Invalid/no-section output is rejected without semantic repair. Each raw question, answer, token usage and input budget is logged.

Jev is fixed to `jev-1.13.0`. LLM refinement is fixed to `qwen/qwen3-coder-next`, endpoint `parasail/bf16`, temperature 0, 4000 output tokens maximum, structured JSON, and no provider fallback. Jev/LLM requests do not retry automatically. Jev timeout is 10 seconds, LLM 60 seconds. Laya calls are serialized and a late result over 10 seconds is discarded; synchronous PyTorch inference cannot safely be force-killed in-process. Warm inference and queueing are included in the plan stage; model loading is separate.

LLM HTTP calls are serialized with one process-wide lock, shared by Jev+LLM and Laya+LLM. Waiting time is included in the reported refinement `elapsed_ms`, stage time and live browser wall time. `raw.local_transport` separates `queue_ms` from `request_ms`; health reports the concurrency limit and queue policy. The 60-second LLM deadline includes waiting plus the provider request. This limits overlap inside one process; it does not impose a request-per-minute rate limit or coordinate separate server processes. Simultaneous live panels can therefore have different queue waits. Use the sequential benchmark for timing comparisons and preserve the live waits as user-experience evidence.

Two earlier live filming calls returned HTTP 429 (run IDs `441223f7fc6d43708c6efe3d6d83fe22` and `191f3ae9deb040f2b31b45e753aac7d6`). Their failed logs are retained. Concurrent calls to the fixed provider are a possible cause, not a proven diagnosis. The queue is a protocol change for subsequent recordings; it adds no automatic retry, fallback or provider change. Do not silently pool earlier and queued live timings.

`/api/refine` requires a plan produced by this server process with the same request and prior spec. This protects provenance and ensures only/+LLM use the same initial plan. Replaying an old run after restart requires re-running `/api/plan`.

All logs live in ignored `runs/*.json`. Success and failure records include run IDs. Laya API cost is 0 and excludes hardware/energy; Jev cost is a published-rate estimate ($0.042/M input tokens, output free; observed September 22, 2026); LLM uses returned `usage.cost` or null if absent. These do not imply quality or a performance ranking.

Only `127.0.0.1` is bound. Host/origin checks allow the backend and Vite's 5178/5173/4173 ports. Static file serving allows `dist/index.html`, `dist/assets/*` with public suffixes and favicons; traversal, dotfiles and symlink escapes are rejected. Requests are JSON only and at most 32 KB; prompts at most 1500 characters. Laya's exact tokenizer budget is checked to reject silent truncation (also applied to Jev when Laya is ready).

Offline security checks:

```bash
python -m unittest server.test_security -v
```

## Optional sequential API sampling

This sampler is **not** run automatically. It sends real paid provider calls. Default is six fixed English app prompts, one repetition, producing 24 result slots. It requires all three providers to be ready. It records schema success/failure, stage and wall times, raw responses and costs. Aesthetic quality and real UI interaction are explicitly `NOT_RUN`.

```bash
.venv/bin/python -m server.benchmark --repeats 1 --budget-usd 1
# Restrict to a single fixed case (4 slots):
.venv/bin/python -m server.benchmark --case stays-editorial
```

A custom preregistered JSON list with `{id, app, prompt}` entries can be passed through `--cases-file`. The exact cases, seeded provider order and source hashes are saved before calls. Sampling is sequential, only/+LLM share a plan, no failed slots are discarded, and no calls are automatically retried. Budget is a conservative local guard using returned/estimated costs, not a provider-enforced spending limit. Results are stored in ignored `runs/benchmarks/<UTC time>/`; no source logs are served to the browser. Shared plan charges are counted once in batch cost; displayed standalone mode costs are not summed as actual charges.
